# PR62 升级兼容与发送保护

这些修正保留共享面板的账号归属、会话、通行密钥和加密存储边界，不改变已有部署的发送时间、文案、目标或浏览器模式。升级代码不等于通行密钥已配置，也不等于消息已送达。

## 先分清运行到哪一层

依次核对：服务运行、巡查完成、定时任务触发、目标通过筛选、实际提交发送、服务端回执接受。前一层正常不能证明后一层正常。

调度日志中的 `due`、`strongConfirmed`、`pending`、`queuedFailures` 应与目标总数对上。`queuedFailures` 是排除分组，也可能来自授权失效或已占用的重试额度，不能直接解释成刚刚发生了同样数量的发送失败。

## 旧全局随机排期和个人计划

- 独立部署保留原全局随机发送窗口。每个目标有自己的当日随机时间，检查间隔不是统一发送时刻；没有到期目标时不应启动账号浏览器。
- 普通用户默认使用自己的已保存个人计划。没有明确迁移依据时，不会被自动加入旧全局任务。
- 已存在的服务端 `legacy_global_schedule` 兼容映射可以让明确选定的旧账号继续使用全局排期。映射、账号归属、启用状态和登录代次都必须仍然有效；个人计划一旦建立，不能继续冒用旧映射。
- 旧全局账号没有个人时区不代表未授权。排期筛选、浏览器预启动和发送前记账使用同一范围校验：全局使用原全局日界，个人使用经授权的个人时区。
- 重新读取最新账号账本时，仍需保留排期时捕获的原授权范围与登录代次。最新持久化行不含临时范围字段，不能因此退回不带范围的发送路径。

个人结束时间同时作用于浏览器排队中的最终发送动作、协议任务入队/领取，以及 Node 每条提交之前。未知结果和正在执行的尝试不会因为截止时间、切换时区或重新保存而自动重试。

## 账号记录、登录和合并

界面、异步任务、登录工作区和发送账本通过 `account_ref` 与 `login_generation` 锁定准确记录。明确的记录引用失效时拒绝操作，不回退到同编号或同昵称的另一条记录。旧的仅编号请求只在可见记录唯一时兼容。

账号合并保留绑定、发送账本、未知结果屏障和重试额度；遇到身份或安全状态冲突时拒绝，不靠丢弃记录完成合并。同一个实际抖音账号的浏览器锁仍共享，不能因为拆成两个平台记录就并行打开。

## 身份检查与 UID 采集不是一件事

发送前的聊天身份检查、明确的发送回执，以及刷新/巡查时被动采集好友 UID 分别承担不同作用。发送路径不额外采集 UID，不意味着关闭身份检查或回执判断。

可选好友聊天保护仍遵循原有 `SPARKFLOW_FRIEND_GUARD` / 标记文件策略，但网页手动、个人任务和定时任务现在读取相同策略。只有已核验的数据来源才能用于保护；页面身份不明确时不能靠重名猜测目标。

## 通行密钥未启用

设置页始终保留“通行密钥”入口。服务未配置验证域名和 HTTPS 来源地址时，显示未启用原因，不提供无效的绑定或移除按钮，密码登录仍可使用。

实际启用仍需正确配置 `SPARKFLOW_PASSKEY_RP_ID` 和 `SPARKFLOW_PASSKEY_ORIGIN`，以及浏览器接受的安全访问环境。显示入口不等于已完成设备绑定，更不等于已做真机 Face ID 验证。

## 旧重试记录跨天

新重试额度记录保存创建时的时区，按适用自然日保护同日额度，并避免更改时区后重复取得额度。

部分旧记录没有时区。对于来源不明的旧行，运行时仍保守拒绝猜测，不能为了恢复发送就清空整个额度表。能够证明原始全局时区和旧写入器截止时间的部署，可以使用[旧重试额度迁移工具](legacy-retry-quota-migration.md)进行带备份、快照校验和独立回读的一次性字段回填。

迁移不会补发消息，不修改账号 Cookie、目标、发送状态或未知结果屏障。需要处理漏发时应另行确认范围，不将迁移或测试通过当成真实发送成功。

## 无 Docker 权限的服务状态

可以通过[只读状态快照](../DouYinSparkFlow/docs/host-status-snapshot.md)向管理员提供固定服务的状态，而不向 Web 容器开放 Docker socket。采集器必须由宿主机运行，放在 Web 不可写、不可执行修改的目录；不确定或过期的快照不能继续显示绿色状态。

状态采集不会启动发送调度或访问抖音账号。以上兼容修正也不改变 headless/headful 模式，不承诺解决平台的 8610 拒绝或间歇性页面加载故障。
